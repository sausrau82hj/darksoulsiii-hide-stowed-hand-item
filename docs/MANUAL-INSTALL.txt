HideStowedHandItem 1.0.0 — manual installation (no scripts)
================================================================
Target: Dark Souls III / Steam / 1.15.0 (64-bit)

This file covers the do-it-yourself route only: you patch your own chr files with ds3tae.
If you use the prepared models pack (ds3-hshi-chr-models-<version>.zip), skip all of it —
that pack is dropped into a mod folder and needs no unpacking, no patch and no backup.

Default game folder, written <game> below:
    D:\Steam\steamapps\common\DARK SOULS III\Game

Where things are in THIS package
    hidestowed.dll            ->  <game>\hidestowed.dll
    hidestowed.ini            ->  <game>\hidestowed.ini
    xinput1_3.dll             ->  <game>\xinput1_3.dll
    docs\MANUAL-INSTALL.txt       this file

    There is no files\ folder and no installer: you copy three files and run
    two commands.  The patcher edits YOUR OWN chr\*.chrbnd.dcx files instead of
    shipping a pre-patched model, so no game assets live in this package.

    The patcher, ds3tae, is NOT in this archive: Nexus uploads may not contain
    executables.  Take ds3tae.dll, ds3tae.deps.json, ds3tae.runtimeconfig.json
    and SoulsFormats.dll out of the tools\ folder of the GitHub repository (or
    build it from validator\, see the README), put them in one folder and run
    dotnet ds3tae.dll from there (it needs the .NET 10 runtime); the commands
    below assume it is on your PATH or in the current folder.

--------------------------------------------------------------------------
0. Back up first (copy these somewhere safe)
--------------------------------------------------------------------------
    <game>\chr\*.chrbnd.dcx            (every character model you are about to patch)
    <game>\xinput1_3.dll               (if it already exists, see step 2)

    This backup is your uninstall: there are no installers, so nothing else
    keeps a copy.  A full 165-model chr\ is roughly 340 MB.

--------------------------------------------------------------------------
1. Copy the mod core and its configuration
--------------------------------------------------------------------------
    hidestowed.dll  ->  <game>\hidestowed.dll      (~191 KB)
    hidestowed.ini  ->  <game>\hidestowed.ini

    The ini ships with usable defaults; the README documents every key.
    The ones that matter for daily use:
        HideLeftHang=1        hide the sheathed left-hand item (two-handing the
                              RIGHT weapon)
        HideRightHang=1       mirror image (two-handing the LEFT weapon)
        HideBothPaired=1      hide the spare model of a one-handed paired weapon
        PairedFields=1,2,3    which models of a paired weapon to hide
        ExtraMods=            other DLLs the shell should load too
                              (comma- or space-separated; empty = none)

    The ini carries only those behaviour keys.  Everything else (Rescan,
    HidePoly, the probe keys) is documented as diagnostics in the README and
    takes its default when absent.

--------------------------------------------------------------------------
2. Copy the loader shell (xinput1_3.dll)
--------------------------------------------------------------------------
    xinput1_3.dll  ->  <game>\xinput1_3.dll                    (~193 KB)

    Its only job is to make the game load hidestowed.dll: it poses as
    xinput1_3 and forwards the XInput exports to the system DLL, so controllers
    are unaffected.

    * If another mod already owns <game>\xinput1_3.dll (a key-prompt mod, a DKP
      loader, ...), overwriting it disables that mod.  Either rename that file
      first or load hidestowed.dll with ModEngine instead — then skip
      this step.
    * Only one xinput1_3.dll can be active at a time.

--------------------------------------------------------------------------
3. Character-model patch (dummies 382/383 in every chr\*.chrbnd.dcx)
--------------------------------------------------------------------------
    Editing 165 files by hand is not practical.  From the folder you unpacked
    this package into:

        dotnet ds3tae.dll parkdir "<game>\chr" INPLACE "382,383" "0,-1000,0" 0 "chrbnd"

    Add DRYRUN as the last argument to see what it would do without writing:

        dotnet ds3tae.dll parkdir "<game>\chr" INPLACE "382,383" "0,-1000,0" 0 "chrbnd" DRYRUN

    Each file is verified before it is written (bone list, materials, meshes
    and buffer layouts must be unchanged, every original dummy entry stays
    untouched); files that already carry 382/383 are skipped, so running it
    twice is harmless.  Close the game first.

    The dummies must exist in every model, or a character in the same stance
    gets a degenerate attachment matrix — black triangles and flicker.

--------------------------------------------------------------------------
4. Verify
--------------------------------------------------------------------------
        dotnet ds3tae.dll verify "<game>\chr" chrbnd "382,383"

    The answer you want:
        scanned N file(s), N with an FLVER … files still carrying 382,383: N

    The second N must equal the first.  If it is lower, some model has no
    parking dummy: run step 3 again, and if that does not help make sure the
    game folder is writable and no antivirus is blocking the files.

    Then start the game and check it in game:
      * left hand holding a shield/weapon, right-hand weapon two-handed -> the
        left item is invisible (not on your back);
      * two-hand the left weapon -> the right item is invisible instead;
      * hold a paired weapon one-handed -> the spare blade is not drawn;
      * cancel the two-hand grip or attack with the sheathed hand -> it comes
        back.

    Nothing happens at all: make sure HideLeftHang=1 and both
    hidestowed.dll and xinput1_3.dll sit directly in <game>.

--------------------------------------------------------------------------
5. If it stutters
--------------------------------------------------------------------------
    Add Rescan=0 to the ini (it is not shipped).  The one-time start-up scan is what walks the
    process's memory regions; with Rescan=0 nothing re-scans after it and the
    mod is reduced to a few reads per second.  Trade-off: if the engine
    rebuilds its parameter table mid-session the effect can stay off until the
    next launch.

    The mod writes no log file, so nothing accumulates in the game folder.  If
    the stutter survives Rescan=0, the parameter scan is not the cause.

--------------------------------------------------------------------------
6. Uninstall
--------------------------------------------------------------------------
    Switch the effect off only:
        set HideLeftHang=0 and HideRightHang=0 in the ini (applies in ~1 s)

    Back to vanilla, by hand:
        a) delete <game>\hidestowed.dll and <game>\hidestowed.ini;
        b) put your backed-up xinput1_3.dll back (or delete the file if you had
           no other loader);
        c) put the character models back from your own copies (step 0).
           Without copies, remove dummy 382/383 from every model:
             dotnet ds3tae.dll stripdir "<game>\chr" INPLACE "382,383" "chrbnd"
           (add DRYRUN as the last argument to only see what it would do).
           The strip restores the models structurally, but a re-serialised
           bundle is NOT byte-identical to the original (DCX re-compression).
           For exact bytes use your own backup, or delete the loose
           chr\*.chrbnd.dcx files and let the game read the packed ones.
           Prove the result:
             dotnet ds3tae.dll verify "<game>\chr" chrbnd "382,383"
           A clean game ends in "verify: CLEAN".

--------------------------------------------------------------------------
7. Troubleshooting
--------------------------------------------------------------------------
* Black triangles / flicker: a character model has no dummy 382/383, so the
  engine builds a degenerate attach matrix.  Prove it with
    dotnet ds3tae.dll verify "<game>\chr" chrbnd "382,383"
  — "files still carrying 382,383" must equal the number of scanned files.
  Setting HidePoly=383 in the ini only helps when the models really carry 383.
* After some launches the item stays on your back (no artefacts): the engine
  keeps several copies of the parameter table and caches resolved attach
  values; restarting the game normally fixes it.
* One character or weapon looks wrong: delete that loose
  chr\<character>.chrbnd.dcx to roll that single file back.
* After a model/armour mod replaced chr\*.chrbnd.dcx: re-run step 3
  (already-patched files are skipped).
* NPCs hide the item too: the parameter table is shared and the dummies are
  valid for every model, so an NPC in the same stance does not draw its
  sheathed item either.
* Online: this mod only changes local memory and local model files, but online
  play has a server-side save check — use it offline.
